## D-01 · Compute = Render free tier (Singapore region)

- **Status:** LOCKED + DPDP-monitored
- **Context:** Need FastAPI hosting for Phase 0-1 + Phase 6 alpha. Zero-CC hard constraint. Fly.io + Railway both require CC in 2026. Render free no-CC.
- **Decision:** Render free (Singapore). Sleeps after 15 min idle (~60s wake). Migrate to Mumbai compute (Fly bom1 + CC) at Phase 4-5 trigger.
- **Consequences:** +50-100ms latency vs Mumbai. DPDP cross-border risk requires monitoring MeitY notifications + privacy-policy disclosure naming Singapore. Migration runbook deliverable in Phase 2 Week 1.

## D-02 · Database = Supabase Mumbai free tier

- **Status:** LOCKED
- **Context:** DPDP residency for PII. Zero-CC constraint. Neon has no India region. Fly Postgres costs $38/mo Basic.
- **Decision:** Supabase Mumbai free (500MB / 50K MAU / no CC). Auto-pauses after 1 week idle; mitigated by D-03 cron-ping.
- **Consequences:** PII stays in India (DPDP-compliant). Migration to paid Supabase ($25/mo Pro) before public launch if MAU > 50K.

## D-03 · Cold-start mitigation = active-hours cron-ping

- **Status:** LOCKED (corrected by /plan-eng-review D2 on 2026-05-28)
- **Context:** Render free sleeps after 15 min idle. 24/7 cron would burn 720h/mo and exhaust 750h Render free allowance.
- **Decision:** GitHub Actions cron every 10 min, scheduled 04:30-16:30 UTC (10:00-22:00 IST) only. ~420h/mo with ~300h headroom for deploys.
- **Consequences:** Off-hours (22:00-08:00 IST) requests pay 60s cold-start. Mitigated by D-03b cold-start UX banner.

## D-03b · Cold-start UX = honest "Bali waking up" banner

- **Status:** LOCKED (added by /plan-eng-review D4 on 2026-05-28)
- **Context:** Off-hours users hit ~60s Render cold-start. Silent spinner depletes goodwill reservoir.
- **Decision:** Mobile detects upload > 5s elapsed → render Bali speech bubble "Ek second bhai, coach jaag raha hai... ~30s." Phase 3 mobile work, ~1 hour effort.
- **Consequences:** Sets expectation honestly. Aligns with Bali older-bhai voice. No infra change.

## D-04 · Photo storage = Cloudflare R2 with jurisdiction=india

- **Status:** LOCKED
- **Context:** DPDP requires Indian-region storage for PII-tagged photos. R2 Mumbai PoP alone does NOT satisfy jurisdiction; must set bucket jurisdiction=india explicitly.
- **Decision:** Cloudflare R2 with `jurisdiction=india` bucket. Endpoint `<acct>.in.r2.cloudflarestorage.com`. Free 10GB, no CC. Presigned PUT URLs (5-min TTL).
- **Consequences:** Zero egress cost; DPDP-compliant. Local Uploads NOT supported on jurisdictional buckets — standard S3 multipart upload only.

## D-05 · Auth = Firebase Phone OTP

- **Status:** LOCKED
- **Context:** Phone-based identity standard for Indian apps. MSG91 + DLT registration is 3-7 days + paperwork. Firebase phone auth sidesteps DLT.
- **Decision:** Firebase Phone OTP. Free 50K MAU. Server verifies via `firebase-admin.verify_id_token()`.
- **Consequences:** ~10K SMS/mo free on Spark plan; migrate to MSG91 + DLT at Phase 3 scale (>500 MAU) if quota becomes binding.

## D-06 · Ground-truth labeler = Claude Opus 4.7 + founder verify

- **Status:** LOCKED
- **Context:** Gate 0a needs photo labels. Founder has Claude subscription. Avoids circular bias of Gemini-labeling-Gemini.
- **Decision:** Opus 4.7 drafts dish-id + portion estimate per photo; founder verifies every single label manually.
- **Consequences:** Zero incremental cost (existing Claude Code subscription). Different LLM family from Gemini-under-test. Manual verification on all 30 (not spot-check).

## D-07 · Macros = deterministic IFCT lookup, never LLM math

- **Status:** LOCKED
- **Context:** LLMs hallucinate numbers. AI-SPEC §1 locked two-step pipeline.
- **Decision:** Vision LLM emits dish-id + portion ONLY. Macros computed by aggregating `dish_decomposition.json` ingredients against `ifct_lookup.json` raw-ingredient nutrition.
- **Consequences:** Macros are auditable + reproducible. ±35% accuracy target depends on portion estimate + decomposition table accuracy, not LLM math.

## D-08 · Dish-decomposition source = layered cascade

- **Status:** LOCKED
- **Context:** Need ~50 dishes decomposed into IFCT-mapped ingredients. Sources: NIN cooked-dish dataset, Tarla Dalal, Unlock.fit, Opus + founder verify.
- **Decision:** Layered cascade: NIN if accessible → Tarla Dalal + Unlock.fit scrape → Opus drafts + founder verifies. Output: `data/dish_decomposition.json` (seeded 2026-05-28 with 50 dishes — founder verification pending).
- **Consequences:** 5-7 hours founder time across Gate 0a kickoff. V1.5 trigger to expand whitelist if ≥5 of 30 test photos hit off-whitelist.

## D-09 · Photo stratification = 10/10/10 single/mixed/thali

- **Status:** LOCKED
- **Context:** Gate 0a per-bucket pass bar must catch thali-bucket failure that aggregate would mask.
- **Decision:** 30 photos, 10 single-dish + 10 mixed + 10 thali. Each bucket independently scored ≥70% dish + ≥60% macros within ±35%.
- **Consequences:** Aggregate pass-fail not used. Curation guidance in `data/photos/CURATION-CHECKLIST.md`.

## D-10 · Circular bias mitigation + V1.5 RD audit trigger

- **Status:** LOCKED with V1.5 trigger
- **Context:** Reviewer flagged using LLM (Opus) to label ground truth for LLM-under-test (Gemini 2.5 Flash) risks circular bias.
- **Decision:** Mitigations: (1) different LLM family, (2) deterministic IFCT macros, (3) founder manual verify every label. Reserve ₹1,500-3,000 RD audit budget — triggered IF Phase 6 alpha real-user accuracy drops below 75% on real photos.
- **Consequences:** Budget pre-allocated. Audit only if trigger fires.

## D-11 · WhatsApp pitch tone = short, direct, founder-voice

- **Status:** LOCKED
- **Context:** Recruiting 20 Trial Users via WhatsApp DM. Honest framing > salesy pitch.
- **Decision:** 3-4 sentence template (see CONTEXT D-11 example). Founder iterates wording per-recruit; tone stays direct.

## D-12 · Commitment bar = verbal yes + WhatsApp confirm

- **Status:** LOCKED
- **Context:** Gate 0c needs ≥10 verbal commitments. "Maybe" / "sounds cool" inflate count without conviction.
- **Decision:** Only unambiguous "yes, send me the link when ready" + WhatsApp confirmation counts. Sets expectation: install + log meals for 2 weeks.
- **Consequences:** Lower-than-vibes commitment numbers but higher fidelity to alpha conversion.

## D-13 · ₹299 WTP capture = open-ended price ladder

- **Status:** LOCKED
- **Context:** Asking "would you pay ₹299?" leads the witness. Need unbiased WTP signal.
- **Decision:** Ask: *"If this app worked exactly like I described, what would you pay per month? ₹0, ₹100, ₹299, ₹499, more?"* Capture verbatim quote. Gate 0c bar = ≥3 quotes with specific ₹ figure.
- **Consequences:** Verbatim quotes weight more than yes/no on ₹299. Calibrates Phase 5 pricing.

## D-14 · Recruit funnel = personal network first

- **Status:** LOCKED
- **Context:** 20 Trial Users needed. Cold outreach via Reddit / DMs harder than personal network.
- **Decision:** Personal network first (gym buddies, college fitness friends, Instagram DMs to known contacts). Reddit / cold-DM only if personal network produces <20.
