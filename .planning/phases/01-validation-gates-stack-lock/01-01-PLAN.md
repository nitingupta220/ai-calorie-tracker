  <name>Task 1: Clone INDB repo and implement INDB.do unit-to-gram rules in Python</name>
  <files>data/indb/recipes.xlsx, data/indb/INDB.xlsx, data/indb/INDB.do, data/indb/recipes_servingsize.xlsx, data/scripts/indb_to_decomp.py</files>
  <read_first>
    Read INDB.do fully before writing a single line of Python. The .do file contains ~45 Stata unit→gram conversion rules. Many are straightforward (g, ml, tsp, tbsp, cup, oz, l). Some are item-specific: "egg" (look up INDB standard weight or default 50g/egg), "piece" (dish-specific — flag for manual review), "slice" (bread slice ~30g), "bunch" (flag for manual review). Any unit not explicitly handled must return None and be flagged in a log file (data/scripts/indb_unit_gaps.csv) rather than silently dropped or guessed.

    After reading INDB.do: read recipes.xlsx columns to understand schema — expected: recipe_name, food_code, amount, unit, ingredient_name columns. Read INDB.xlsx for per-100g macro columns. Read recipes_servingsize.xlsx for per-serving macro summaries (used to cross-validate ingredient-level sums).

    Do NOT write the UNIT_G dict from memory. Copy the exact multiplier values from INDB.do. The .do file is the authoritative source; training-knowledge approximations (e.g., "tsp ≈ 4.2g") may differ from INDB's chosen conventions.
  </read_first>
  <action>
    Clone the INDB GitHub repo into data/indb/ using: git clone https://github.com/lindsayjaacks/Indian-Nutrient-Databank-INDB- data/indb/

    Install dependencies if not present: pip install pandas openpyxl (Python 3.12 is confirmed available).

    Write data/scripts/indb_to_decomp.py. The script does five things:

    1. LOAD: Read data/indb/recipes.xlsx into a DataFrame. Read data/indb/INDB.xlsx for per-100g macros. Read data/indb/recipes_servingsize.xlsx for per-serving macro totals.

    2. UNIT→GRAM CONVERSION: Build UNIT_G dict from exact values in INDB.do (read the file first — each "replace amount_g = amount * X if unit == Y" line maps to UNIT_G["y"] = X). Apply to every row. Rows where unit is not in UNIT_G and cannot be resolved: set amount_g = None, write recipe_name + food_code + unit + amount to data/scripts/indb_unit_gaps.csv. Never guess or average over None rows.

    3. WHITELIST MAPPING: Build a mapping dict from INDB recipe names to the 50 whitelist dish_id keys in data/dish_decomposition.json. This mapping must be explicit (not fuzzy-auto) because INDB recipe names are ambiguous (e.g., "Tur Dal" could map to dal_toor_tadka or dal_toor_plain). For dishes where multiple INDB recipes could match (e.g., "dal_toor_tadka" vs "dal_toor_plain"), pick the tadka/cooked variant as the default and add the plain variant to _variants. Write the mapping as a Python dict in the script (not hardcoded JSON) so it is auditable. The script prints unmapped whitelist dishes so gaps are visible.

    4. DECOMPOSITION OUTPUT: For each mapped whitelist dish, produce the ingredient list in the target schema: [{"ifct_id": "<key>", "g": <float>}]. The ifct_id must be a key that exists in data/ifct_lookup.json. If an INDB ingredient food_code has no corresponding ifct_lookup.json entry, write it to data/scripts/indb_ifct_gaps.csv (food_code, ingredient_name) and skip that ingredient from the output (log the skip explicitly). Set verified_by to "INDB recipe #<recipe_id> + INDB per-serving macros (<date>)". Set _indb_recipe_id.

    5. VARIANTS: After the main mapping loop, add a _variants list to fat-heavy dishes where INDB has a single fixed oil amount. Specifically: dal_toor_tadka, dal_makhani, paneer_butter_masala, palak_paneer, butter_chicken (non-veg). Each gets _variants: ["<dish_id>_plain", "<dish_id>_restaurant"] and default_variant: "<dish_id>" (the INDB-seeded row is the middle estimate).

    The script outputs a JSON object (not the full dish_decomposition.json — just the INDB-sourced dishes dict) to data/scripts/indb_dishes_output.json. This is merged into dish_decomposition.json in Task 2.

    Run the script after writing it: python data/scripts/indb_to_decomp.py. Check that indb_unit_gaps.csv and indb_ifct_gaps.csv are written (empty is fine if all units resolved). Check that indb_dishes_output.json has entries for the ~43 whitelist dishes.
  </action>
