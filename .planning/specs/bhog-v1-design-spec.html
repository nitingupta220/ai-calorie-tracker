02

Design System · Coach Dark

Dark default. Warm charcoal background. Copper-amber primary accent. Ivory text. Sage secondary. Spacious one-card density. Spring motion + coordinated haptics. Distinct from every direct competitor.

Philosophy

  • Dark default. Light theme V2 only if requested.
  • Spacious, one-card-at-a-time. Persona judges quality by whitespace.
  • Restrained accent. Copper-amber only on intent / focus / CTA.
  • Numerics are mono. Macros + ₹ + dates use IBM Plex Mono tabular figures.
  • Motion = spring. Cubic-bezier reads dated.

Avoid

  • Saffron primary — BJP/Hindutva political signal post-2022.
  • Neon-on-black — peaked 2023.
  • HealthifyMe-green — owned by incumbent.
  • Bridal gold — wrong cultural register.
  • Red as brand — keep for warning state only.
  • Illustrated food — undermines photo-to-macros hook.

Vision Accuracy · Reality Check

External-review-verified

Fact-checked against primary sources (Nutrition5k CVPR 2021 · GPT-4V Nutrients 2025 · Martin 2018). Recognition is the easy ~20%; the binding error is portion + hidden fat. Full detail in PITFALLS.md V-01..V-06. One reviewer claim ("68%→21% churn / AI churns 30% faster") FAILED verification and is omitted as unsourced.

V-01 · Recognition ≠ calorie accuracy

Dish-ID is solved: ~87–93% (MobileNetV3), GPT-4V 93% precision. But the same GPT-4V study: 11/16 nutrients significantly wrong. Naming "paneer butter masala" says nothing about 280 vs 450 kcal. → score dish-ID + macros separately (Gate-0a F-15).

V-02 · Portion-from-2D is ill-posed

Monocular scale ambiguity — geometry, not model quality. Verified floor: image-only calorie error ~26.1%; depth halves it to ~16.5% (Nutrition5k, Table 3). We have no depth → reference object (coin/palm) is the scale prior. ±35% ok on the mean, fails on the tail.

V-03 · Hidden oil/ghee is invisible

1 tbsp oil = 120 kcal, no pixels. "Dal" spans ~100–400 kcal by tadka. A second error source stacked on portion. → dal_plain / dal_tadka / dal_restaurant variants + one-tap selector; market "estimate/range".

V-04 · Human accuracy ceiling

People get only 5/20 photos within ±20% (Martin 2018, n=2,028). So "not perfect" is the defensible target — and user corrections are a noisy signal, founder eyeball portions too (→ weigh the truth).

V-05 · Indian cuisine stacks everything

Thali = multi-item segmentation × portion ambiguity × hidden fat × regional variance → 40–60% total error, outside any published result. → thali reported-only (F-15), "snap each item" UX, V1.5 re-intro.

V-06 · Ground-truth bottleneck

Every free Indian dataset = recognition labels only, NOT weighed grams. → weigh the 30 benchmark plates + ingest INDB (recipe grams). Until then a Gate-0a pass ≠ field accuracy.

Dataset verdict
No free Indian dataset can serve as macro ground truth — all (Indian Food Images 4k/80-class, IndianFoodNet-30, etc.) are recognition labels only. Weighed-gram truth exists only Western (Nutrition5k CC BY 4.0, SimpleFood45) — calibrates methodology, not Indian macros. Indian macro layer = IFCT 2017 + INDB (Indian Nutrient Databank): ~1,014 recipes with per-ingredient grams + per-serving macros, open-access, IFCT-derived → ingest alongside IFCT (D-21 / TODOS-9). Gate-0a truth must be weighed by the founder.
Competitive reality
HealthifyMe "Snap" (Sept 2023) already ships this: 150k items, GPT-4 Turbo Vision + fine-tuned ensemble + humans-in-loop, ~75% accuracy, 40M+ users (OpenAI case study). Even the incumbent caps ~75% with far more — so the moat is NOT photo accuracy; it's budget-aware veg-protein-gap advice grounded in the user's own log. Strategic pivot (diaspora / GLP-1) logged OPEN in D-29, not decided.

Provider free-tier rate limits

MOAT

Advice "on the side" temptation

Doc corrected to inline-on-every-card. If P3 UI ever buries advice in coach tab, moat collapses. Locked Invariant in Card Demo.

DEMAND

No verbatim ₹299 quote yet

Gate 0c closes this Week 1. Below 3 quotes → pricing thesis weakens → re-evaluate paid tier model before Phase 5.

VISION

Thali photo accuracy untested

Lit shows 49–76% error on multi-item dishes. Gate 0a thali bucket tests. Fail → "snap each item separately" UX V1.

V1.5

Two-persona temptation

"Target both" instinct re-surfaces. V1 locks one (youth muscle-gain). Weight-loss = V1.1 trigger-gated. Housewife = V2 separate brand.

V2

Cal AI competitive durability

Cal AI can ship Indian context with prompt update. Real durable moat = dataset (post-PMF) + brand. 6–12mo head-start realistic, not "forever."

GROUND-TRUTH

Our "truth" may be wrong the same way the model is

Gate-0a truth macros = founder's eyeballed portion_g run through the Opus-drafted (verified_by:null) decomposition table — the same pipeline that scores Gemini. So the gate measures agreement-between-two-estimates, not accuracy. Circular on portions, not just labels (D-10). Until plates are weighed + rows verified, a pass ≠ field accuracy. Verified: humans get only ~5/20 photos within ±20% (PMID 30401671).

ACCURACY-CEILING

Image-only calorie error floors at ~26%

Best published single-RGB calorie model = ~26.1% mean error; only depth (which we lack) halves it to ~16.5% (Nutrition5k, CVPR 2021). Geometry-driven (monocular scale ambiguity), measured on clean Western plates — Indian phone photos + hidden ghee + thali are harder. ±35% is fine on the mean, fails on the tail. → market "estimate/range", enforce reference object, moat = veg-protein advice not exact kcal.

COMPETITION

HealthifyMe "Snap" already shipped this (2023)

Launched Sept 2023: 150k food items, GPT-4 Turbo Vision + fine-tuned ensemble + humans-in-loop, ~75% accuracy, 40M+ users (verified, OpenAI case study). Lesson that helps us: even the incumbent uses GPT-4V plus fine-tuned plus humans and still claims only ~75% — validates anti-pattern #4. Moat is NOT photo accuracy (capped ~75%); it's budget-aware veg-protein-gap advice grounded in the user's own log. Direct AI-photo rivals: Shellel, NutriScan, FitTrack AI.
