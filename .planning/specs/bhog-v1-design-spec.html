02

Design System · Coach Dark

Dark default. Warm charcoal background. Copper-amber primary accent. Ivory text. Sage secondary. Spacious one-card density. Spring motion + coordinated haptics. Distinct from every direct competitor (HealthifyMe-green, Cult.fit-orange, Whoop-red, Hevy-lime, Cred-grey, Cal AI-green). Founder's "not too bright" instinct validated by 2026 dark-mode preference data + global anti-neon gym aesthetic shift.

Philosophy

  • Dark default. Light theme V2 only if requested.
  • Spacious, one-card-at-a-time. Persona judges quality by whitespace.
  • Restrained accent. Copper-amber appears only on intent / focus / CTA — not as background.
  • Numerics are mono. Macros + ₹ + dates use IBM Plex Mono tabular figures.
  • Motion = spring. Cubic-bezier reads dated; spring physics matches AI-think pacing.

Avoid

  • Saffron primary — BJP/Hindutva political signal post-2022.
  • Neon-on-black — peaked 2023, reads dated.
  • Bright HealthifyMe-green — owned by incumbent, reads pharma-cheap.
  • Bridal gold — wrong cultural register for fitness.
  • Red as brand — keep red for warning state only.
  • Illustrated food — undermines photo-to-macros hook.

Deployment Strategy

FREE · NO CC

Constraint: founder has no credit card / no runway. Every service in Phase 0–1 must work on free tier without CC. Fly.io and Railway both eliminated in 2026 (CC required). Stack below is verified free-no-CC.

Compute · Render free (Singapore)

Push-to-deploy from GitHub. Sleeps 15min idle, ~60s wake. No CC at signup. +50–100ms latency vs Mumbai-native — acceptable for Phase 0–1. Cross-border processing DPDP-compliant with privacy-policy disclosure.

Postgres · Supabase Mumbai free

500MB, 50K MAU, India region. Auto-pauses after 1wk idle. Defeated by GitHub Actions cron-ping every 6hr against /healthz.

Photo storage · R2 jurisdiction=india

Endpoint <acct>.in.r2.cloudflarestorage.com. Mumbai PoP alone is NOT data-residency — bucket must be created with explicit jurisdiction param. Free 10GB.

Auth · Firebase Phone OTP

50K MAU free. No DLT registration overhead (vs MSG91 SMS). Server verifies ID tokens via firebase-admin.

Phase 1 alpha keep-warm

GitHub Actions cron every 10 minutes hits Render /healthz during the 14-day alpha window. Disable after alpha to conserve Actions minutes. Mobile-side cache layered on top (Phase 3 build).

AI Decisions

AI-SPEC v1

Full contract: .planning/phases/01-validation-gates-stack-lock/01-AI-SPEC.md (937 lines, locked).

System classification

Hybrid · Structured Extraction (vision → dish + portion + macros) + Grounded Content Generation (advice from last-3-day meal log). NOT RAG (SQL retrieval, no vector store). NOT agentic (no tool-calling, no plans). NOT conversational (single-turn per meal).

Framework decision

Direct SDKs + Pydantic v2 behind ai_provider.py abstraction. No LangChain / LangGraph / LlamaIndex / CrewAI. Deterministic two-step pipeline doesn't justify framework abstraction tax. Zero framework lock-in: provider swap = swap one file.

Pipeline · single API response, <8s P95

POST /meals/photo  (multipart presigned)
   │
   ▼
[1] presigned PUT to R2 india jurisdiction          ── mobile → R2 directly
[2] FastAPI receives photo_url + user context
[3a] VisionProvider.identify(photo_url)             ── Gemini 2.5 Flash
       returns: { items: [{name, portion_g, conf}] }
[3b] DishDecomposer.macros(items)                   ── deterministic
       JSON lookup → IFCT 2017 aggregate
[4]  asyncio.gather(
       persist_meal(macros),
       AdviceProvider.coach(user, last_3d, dish)    ── Groq Llama 3.3 70B
                                                       6s hard timeout
     )
[5] rubric_validator.score(advice)                  ── 4/4 check
       ├─ 4/4 → render
       ├─ <4/4 → retry once

       ▼
Mobile renders MacrosCard with inline AdviceInline child

Critical failure modes (mitigations baked into spec)

Wrong dish / fabricated macros

Stratified Gate 0a benchmark · Pydantic schema validation · two-step pipeline (IFCT lookup, never LLM math) · confidence-gated UI on >3 items or conf<0.6.

Generic advice

Server-side 4/4 rubric validator rejects advice missing food + quantity + ₹ + log reference · retry once · per-dish template fallback · WoZ QA Gate (≥35 founder-written examples, ≥70% AI-vs-WoZ match) before alpha.

PII to LLM provider

Lint rule in CI bans user.name/phone/dob in advice-prompt path · only de-identified user_id + goal/macros/diet preference fields.

Vendor lock-in / rate-limit shock

ai_provider.py 429-fallback chain · lint ban on provider SDK imports outside providers/ · per-call cost log + tag · pre-launch load test (20 concurrent at dinner-hour) · OpenRouter fallback drill (10% traffic 24h) before alpha.

Photo-to-macros is now table stakes. The unoccupied wedge is inline, culturally-grounded, budget-aware advice rendered on every meal card, free in V1. Moat layers (two stacked + proof points)

L1 · Technical — photo-history-grounded advice

AI reads last 3 days of user's actual meals → generates specific recommendations citing the user's own log. Cannot be cloned without per-user data. Switching cost compounds with retention.

L2 · Brand — trainer-replacement positioning

"Replace your ₹3,000/mo gym trainer with ₹299/mo AI." HealthifyMe / Cult.fit cannot claim this — they sell human coaches. Brand claim is ownable.

Proof points: veg-protein-gap solver · ₹/g cost-aware advice · 50-dish pan-Indian recognition · CDSCO/ASCI-clean disclaimer hygiene · inline rendering invariant.

Open Risks & Reviewer Concerns

CIRCULAR-BIAS

Opus labels another LLM

D-06 uses Opus 4.7 to label ground truth for Gemini 2.5 Flash under test. Different family + IFCT-deterministic macros + every-label verification mitigate. RD audit reserved as V1.5 trigger if Phase 6 alpha shows real-user accuracy collapse.

TIMELINE

First-time RN shipper drift

14-week target may stretch to 18–20 for first-time React Native shipper. Mitigation: Expo managed workflow, Hello-World Week 1, EAS Build configured Week 1, pre-budget 5–10 day buffer.

VENDOR

Provider free-tier rate limits

Gemini 10 RPM caps at ~50 lunch-concurrent users. Mitigation: 429-fallback chain, OpenRouter fallback drill (10% traffic 24h), per-call provider tag for attribution, pre-launch load test before alpha.

MOAT

Advice "on the side" temptation

Founder framed advice as "on the side" earlier — doc has corrected to inline-on-every-card. If Phase 3 UI ever buries advice in a coach tab, moat collapses. Locked as Invariant in Card Demo section.

DEMAND

No verbatim ₹299 quote yet

Gate 0c closes this in Week 1. If fewer than 3 ₹299 quotes captured → pricing thesis weakens → re-evaluate paid tier model before Phase 5.

VISION

Thali photo accuracy untested

Literature shows 49–76% error on multi-item Asian dishes. Gate 0a thali bucket tests directly. If fails: "snap each item separately" UX in V1, multi-item-single-photo to V1.5.

V1.5

Two-persona temptation

"Let's target both" instinct re-surfaces. V1 locks one persona (urban youth muscle-gain). Weight-loss = V1.1 trigger-gated on muscle-gain D7 ≥25% + advice 4/4 ≥75%. Housewife persona = V2 separate brand.

V2

Cal AI competitive durability

Cal AI can ship Indian context with a prompt update. Real durable moat = dataset (post-PMF) + brand (Trainer-Replacement is ours). 6–12mo head-start realistic, not "forever."
